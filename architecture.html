High-level topology

Three discovery surfaces. One shared infrastructure.

Claude Code discovers each layer by convention: .claude/skills/<name>/SKILL.md, .claude/commands/*.md, .claude/agents/*.md. Symlink-installable per project or user-wide.

Skill anatomy

Each skill is a self-contained unit.

skills/<skill>/ ├── SKILL.md front-door: name, description, modes, triggers ├── agents/ sub-agent personas used internally by this skill │ ├── question-formulator.md │ ├── source-searcher.md │ └── synthesizer.md ├── references/ methodology / standards docs │ ├── prisma-2020.md │ ├── socratic-method.md │ └── apa7-citation.md ├── templates/ output structure templates per mode │ ├── brief-report.md │ ├── systematic-review.md │ └── verification-report.md └── examples/ synthetic worked examples for prompt grounding

SKILL.md uses YAML frontmatter to declare name, description, trigger phrases, and the mode list. Claude Code's skill loader reads this and surfaces the skill.

Mode taxonomy

A mode is a parameterization, not a separate skill.

Axis Values What it controls
Spectrum bias Generative · Hybrid · Analytic How the skill weights creativity vs verifiability vs questioning.
Deliverable brief · report · dialogue · audit · format · disclosure What artefact (if any) the mode produces.
Oversight Low · Medium · High · Very High How often the user is asked to approve mid-flow.
Triggers natural-language patterns What activates the mode when no slash command is used.

Modes branch within a skill's logic. 24 modes across 4 skills. Canonical list in MODE_REGISTRY.md.

Provenance

Every claim is anchored to one of three sources.

Cited source
External reference with locator: page, section, or paragraph. The default and most common.
User input
A value the user supplied. Anchored by timestamp or message reference from the session.
Framework computation
Internal aggregation (e.g., "synthesis across sources A, B, and C"). Always explicitly marked as such.
<unverified>
No anchor available. Claim is flagged and moved to a notes section. Not published as fact.

The verification chain is what makes the difference between "fluent AI prose" and a defensible artefact.

Slash command layer

Thin shortcuts. Skill + mode in one frontmatter.


# commands/research-verify.md
---
description: Claim-by-claim fact-check with source locators
model: sonnet
---
 
Invoke the `research` skill in **verify mode**.
This mode takes a piece of text and checks each factual claim
against external sources. It produces a verification report,
not a rewrite.
...

24 commands ship with v1.0.0, one per mode. Discovered by Claude Code from .claude/commands/*.md. Model override is optional; otherwise the command inherits.

Extension points

How to add a skill, mode, or sub-agent.

Adding a new skill
  • 1. Create skills/<new>/SKILL.md
  • 2. Add modes to MODE_REGISTRY.md
  • 3. Add sub-agents under skills/<new>/agents/
  • 4. Add slash commands under commands/
  • 5. Update README skill matrix
Adding a mode to an existing skill
  • 1. Update the skill's SKILL.md frontmatter
  • 2. Add mode logic to skill prompt body
  • 3. Add the mode to MODE_REGISTRY.md
  • 4. Optionally add a slash command

Versioning is semantic: MAJOR breaks skill API or file structure; MINOR adds skills/modes/non-breaking enhancements; PATCH fixes prompts or docs. See CHANGELOG.md.

Architecture summary

Three layers, one rule:
provenance over fluency.

Discovery
Three convention-based surfaces (.claude/skills, .claude/commands, .claude/agents) registered with Claude Code.
Execution
Skill + mode parameterizes workflow. Sub-agents do specialized work. Checkpoints enforce human approval. Two-loop revision cap.
Audit
Every claim anchored to source, user input, or framework computation. Pipeline-logbook captures decisions. Disclosure mode regenerates the audit trail for venues.
